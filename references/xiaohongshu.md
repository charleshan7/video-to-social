# 小红书卡片规范

## 硬约束

- 图 `1080×1440`（3:4 竖版），**最多 18 张**
- 正文建议 **950 字以内**，话题标签也算字数，给平台发布留余量
- **首图决定点击率**，必须是大标题卡
- 顺序不能乱（卡片之间有叙事）
- 标题栏与卡片上的标题是两回事，要单独填

## 和公众号的根本差别

公众号是**读**——长文、图文交替、可以慢慢展开。
小红书是**先扫图再决定读不读**——信息必须在图里，正文只是引流。

所以内容同源，但结构要重做：不能把长文切段贴上去。

## 版式库

每页换一种版式，不复用模板。这套在实战里验证过：

| 版式 | 构成 | 适合 |
|---|---|---|
| **首字下沉** | 栏目线 + drop cap 段落 + 若干段 + 图落底 | 人物出场、叙事开头 |
| **大数字组** | 2~3 个大数字 + 小字标签 + 正文 | 关键指标、前后对比 |
| **pull quote** | 上下发丝线夹住的大字引语 + 图 | 金句、观点页 |
| **满幅图 + 段落** | 图通栏 + 图注 + 3~5 段 | 信息型幻灯片 |
| **编号条目** | `01/02/03` + 粗体词 + 说明 | 并列的证据、功能清单 |
| **纯文字页** | 粗线 + 导语 + 条目 + 收尾引语 | 论述密集处，用来换气 |
| **收尾页** | 主线收束 + 大字引语 + 互动提问 | 最后一张 |

### 节奏

- **深底页穿插在浅底页之间**（终端截图、暗色幻灯片），滑动时有明暗呼吸
- **人物页分散**在开头、中段、结尾，标出讲者切换的节点
- **不强求每页有图**，纯文字页是调节节奏的手段

## 排版参数

```
卡片            1080×1440，padding 64px 62px 48px
底色            #FCFBF9（比纯白柔和）
顶栏            21px 等宽字体，字距 .16em，#A5A5A5，右侧 01/17 页码
标题            46px / 700 / line-height 1.32
正文            31px / 300 / line-height 1.8
图注            19~20px / #A5A5A5 / 居中
大数字          76px / 700 / letter-spacing -.03em / tabular-nums
pull quote      44~52px / 700
底栏            21px + 上边框
```

## 三个反复踩的坑

**1. 内容不够却用 `fill` 把底部元素顶到底 → 中间一个大洞。**
补内容，或者整块垂直居中让留白平分到上下两端（纯引语页适合后者）。

**2. `object-fit:cover` 裁掉原帧上下。**
为了塞进固定高度而裁图，可能正好切掉人物的姓名角标。
人物图一律用自然高度满幅（1080×608）；只有截图类画面（手机 UI、网页）才可以裁边缘。

**3. 图上压字压不住。**
底图是终端代码或密集界面时，压多深的蒙版都在跟正文抢注意力。
要么给底图 `blur(2.4px) saturate(.55) brightness(.72)` 退成肌理，要么干脆图文分离。
终端类底图建议直接放弃压字。

## 正文文案

```
第 1 行     抓人的判断句（信息流里只显示前两行）
第 2 段     核心论点
中段        编号列出 5~6 个要点，每条一两句
结尾        一句收束 + 互动提问（评论区是权重来源）
标签        7~10 个，别堆太多
```

控制在 **950 字以内**留余量。

## 生成方式

HTML + 无头 Chrome 截图，比任何图形库都可控：

```bash
"\${VIDEO_TO_SOCIAL_CHROME:-google-chrome}" \
  --headless --disable-gpu --no-sandbox --hide-scrollbars \
  --window-size=1080,1440 --force-device-scale-factor=1 \
  --virtual-time-budget=6000 \
  --screenshot=01.png "file:///abs/path/card.html"
```

图用 base64 data URI 内联进 HTML，避免相对路径问题。

推荐用素材 ID 引用图片：

```python
XHS_CARDS = [
    dict(layout="hero", title="标题", lead="副题"),
    dict(layout="image", fig="speaker-01", paras=["正文"]),
]
```

数字 `fig` 仍兼容旧内容，但新增素材时可能改变序号，新的卡片应使用 `ASSETS` 中的稳定 ID。构建前运行 `python3 scripts/validate_content.py --channel xhs`；它会检查最多 18 张、第 01 张为 `hero`、素材引用和正文建议不超过 950 字。
